## Finding

- **Finding 1 — pass-rate axis was broken; now fixed.** All runs recorded `0% / recorded-fail`, but
  the apps compiled. Single cause: the `role-per-story` (`role-field-in-stories`, TG-38) artifact-lint
  couldn't parse the `dev`/`main` template's `## Roles`-heading story format — a false negative.
  **Fixed** in `tier-1-unit/artifact-lint/linters.ts` (`extractRole` now handles the heading form;
  merged to `main` as `647bcaf`). Re-scoring the three builds gives the **corrected** rates above:
  build and plan-run-2 were actually **conforming (100%)**; plan-run-3 legitimately fails because 3 of
  its 5 stories omit the Role field entirely.
- **Finding 2 — the "2/3/4 epics" wobble was a harness metric bug, not the benchmark (now fixed).**
  Initially read as unstable decomposition, but all three runs actually built the **same 2-epic
  deliverable** (Notes + Tasks). The `plan` scenario *also* plans and **parks** two extra epics
  (User Settings, Saved Views) by design — never builds them. `epicsBuilt` was computed as
  "epics with ≥1 story file", so parked epics (which `/plan` writes stories for) were miscounted as
  built, and a built-then-branched epic was missed — giving the false 2/3/4. **Fixed** in
  `Get-Tier3EpicStats` (built = built-phase `state.json` **or** epic-end commit across `git log --all`,
  minus parked); re-scored, all three now report `epicsBuilt=2`. So the build-vs-plan comparison is
  actually **valid on the built deliverable** — the old metric was tripping the same-deliverable
  guardrail with a false mismatch.
- **Cost / time (directional, tiny n):** plan ran ~2× tokens and ~+81% Claude time vs build. Both
  arms built the same 2 epics, so this is a *legitimate* comparison — but the extra cost is the
  `plan` arm **planning 2 more epics ahead** (parked, not built). Read it as "the price of `/plan`
  forward-planning", not "same work costs more". Not a firm number at n=1/2.
- **Peak memory:** all three fit 16 GB comfortably (15.0–16.4 GB); `plan` peaked *lower* than `build`.
  `concurrent` was not run, so the two-live-sessions RAM question is still open.
- **Side-signal (n=1, not a conclusion):** one `plan` run (123157) dropped the Role field from 3 of
  its 5 stories — a real quality slip in that run. Both plan runs built the same 2 epics, so this is
  a per-run quality wobble, not an epic-count effect.
- **n / confidence:** build n=1, plan n=2; batch incomplete (network). Far too small for any delta;
  treat all numeric gaps as noise.
- **Verdict:** A **valid pilot shakedown** that produced no firm cost number (n too small) but found
  and fixed **two harness bugs** — the role-per-story linter false-negative (Finding 1) and the
  `epicsBuilt` miscount (Finding 2). With both fixed, a proper batch can now be trusted.
- **Caveats hit:** stale recorded metrics (pass-rate and epicsBuilt corrected post-hoc); lost run 4
  to a network blip; single-machine peak memory inflated by other processes (see per-run report).
